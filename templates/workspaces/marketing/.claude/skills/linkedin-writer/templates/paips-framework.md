# PAIPS Framework — Post-structuur

**Bron:** Justin Welsh (276K impressions, 600+ email subs op één post)
**Gebruik:** Volledige post-structuur voor posts die naar een oplossing/aanbod leiden.
**Sterkste voor:** Consulting-gerelateerde posts, audit-promotie, product/SaaS-posts.

## De 5 stappen

### 1. Problem — Benoem de pijn (= je hook)

Begin met een herkenbaar, pijnlijk probleem. Dit IS je hook — moet binnen 210 chars.

```
Je AI-project heeft €15.000 gekost en levert niets op.
```

```
Je team besteedt 20 uur per week aan rapportages die niemand leest.
```

```
Je SEO-bureau stuurt elke maand een rapport. Je snapt er niets van.
```

### 2. Agitate — Maak het erger (= je re-hook + context)

Verdiep de pijn. Maak de lezer ongemakkelijk genoeg om een oplossing te willen.
Dit is het meest onderschatte onderdeel — de meeste posts slaan dit over.

```
En het ergste: je weet niet eens waarom het mislukte.
Was het de technologie? Het team? De leverancier?
Niemand kan het je vertellen. Want niemand heeft het gedocumenteerd.
```

```
Ondertussen betaal je €2.000 per maand aan een bureau
dat je niet kan uitleggen wat ze doen.
```

### 3. Intrigue — Introduceer iets onverwachts

Breek het patroon. Geef een hint naar een andere aanpak zonder de oplossing te onthullen.

```
Ik bouwde een ander systeem.
Elke beslissing wordt gelogd. Elke fout is traceerbaar.
Het kost een fractie van de vorige aanpak.
```

```
Ik scande honderd vergelijkbare websites met dezelfde checks.
De resultaten waren verhelderend.
```

### 4. Positive Future — Schets het resultaat

Laat de lezer zien hoe het eruitziet als het probleem opgelost is.

```
Stel je voor: je MT krijgt een concreet voorstel.
Concrete stappen. Geschatte ROI. En een eerlijk advies
of de oplossing voor jullie wél of niet zinvol is.
```

```
Binnen 48 uur weet je precies waar je website lekt.
Een actieplan in gewoon Nederlands. Prioriteit per actie.
Je kunt maandag beginnen.
```

### 5. Solution — Jouw aanbod (subtiel, in de footer)

De oplossing zit NIET in de post-body. Die zit in de footer.
De post eindigt met de takeaway, de footer doet de rest.

## Compleet voorbeeld

```
Je AI-project heeft €15.000 gekost en levert niets op.

En het ergste: niemand kan je vertellen waarom.
Geen documentatie. Geen architectuur. Geen audit trail.
Je hebt een systeem gekocht dat niemand begrijpt.

Ik bouwde het anders.
Een open systeem waar elke beslissing zichtbaar is.
Elke fout traceerbaar. Geen black box.

Het resultaat: lagere kosten. Hogere snelheid. Nul verrassingen.

Het verschil? Architectuur vóór implementatie.
Niet een rapport. Een werkend systeem.

———
Een korte CTA die past bij jouw aanbod (uit brand-voice.md).
```

## Wanneer PAIPS gebruiken

- Posts die een probleem-oplossing boog volgen
- Consulting/audit-gerelateerde content
- Product/SaaS-posts met een conversie-doel
- Posts waar je je aanbod subtiel wilt positioneren

## Wanneer NIET gebruiken

- Pure thought leadership / contrarian takes → gebruik VFA of text-only structuur
- Build logs / proof of work → gebruik de standaard post-structuur
- Breaking news → geen agitate-fase nodig
